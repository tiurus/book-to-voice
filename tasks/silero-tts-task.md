# Задача: локальный сервис русской озвучки на Silero TTS

## 1. Цель

Разработать локальный веб-сервис, который принимает русский текст, озвучивает его с помощью open-source модели Silero TTS и позволяет прослушать либо скачать результат.

Сервис должен работать на MacBook Air с Apple M1 и 16 ГБ оперативной памяти без обращения к платным внешним API. Текст пользователя и созданные аудиофайлы не должны покидать компьютер.

## 2. Исходные условия

- Устройство: MacBook Air, Apple M1, 8 ядер, 16 ГБ RAM.
- Архитектура: ARM64.
- Операционная система: macOS 26.5.2.
- Доступный Python: Homebrew Python 3.12.12.
- Свободное место: около 59 ГБ.
- PyTorch, Silero TTS и FFmpeg пока не установлены.
- Основной режим работы: локально, на CPU.

## 3. Важное ограничение по лицензии

Русские модели Silero V5 распространяются под лицензией CC BY-NC, поэтому первая версия сервиса предназначена только для личного и некоммерческого использования.

Перед коммерческим запуском необходимо отдельно выбрать модель и голос с лицензией, разрешающей коммерческое использование, либо получить соответствующее разрешение правообладателя.

Источник: [репозиторий Silero Models](https://github.com/snakers4/silero-models).

## 4. Пользовательский сценарий

1. Пользователь открывает сервис в браузере на локальном адресе.
2. Вставляет русский текст в поле ввода.
3. Выбирает голос и параметры чтения.
4. Нажимает кнопку «Озвучить».
5. Видит состояние генерации и возможные ошибки.
6. Прослушивает запись во встроенном аудиоплеере.
7. Скачивает результат в WAV или MP3.
8. При необходимости меняет настройки и создаёт новую версию.

## 5. Функциональные требования

### 5.1. Ввод текста

- Многострочное поле для русского текста.
- Счётчик символов.
- Начальное ограничение: 5 000 символов на одну генерацию.
- Проверка пустого ввода.
- Корректная обработка кириллицы, знаков препинания, `ё`, чисел и аббревиатур.
- Длинный текст необходимо делить на безопасные фрагменты, не разрывая предложения без необходимости.

### 5.2. Выбор голоса

Использовать актуальную русскую модель Silero `v5_5_ru` либо последнюю совместимую русскую V5-модель.

Предоставить доступные голоса:

- `aidar`;
- `baya`;
- `kseniya`;
- `xenia`;
- `eugene`.

Перед началом основной разработки проверить фактическую доступность голосов в выбранной версии модели.

### 5.3. Настройки озвучки

- Голос.
- Частота дискретизации: по умолчанию 48 000 Гц.
- Скорость воспроизведения или постобработки: минимум три варианта — медленно, обычно, быстро.
- Возможность включить автоматическую обработку ударений и омографов, если она поддерживается выбранной моделью.
- В расширенном режиме — поддержка допустимых SSML-настроек Silero.

### 5.4. Генерация аудио

- Генерация выполняется локально через Silero TTS.
- Базовый формат генерации — WAV.
- MP3 создаётся локально через FFmpeg.
- При обработке нескольких фрагментов итоговое аудио должно объединяться в правильном порядке без обрезанных слов и заметных технических щелчков.
- Имена временных и итоговых файлов должны генерироваться безопасно и не зависеть напрямую от пользовательского текста.
- После генерации сервер возвращает длительность, формат и размер файла.

### 5.5. Прослушивание и скачивание

- Встроенный HTML-аудиоплеер.
- Кнопки скачивания WAV и MP3.
- Кнопка удаления текущего результата.
- Новая генерация не должна автоматически удалять предыдущий файл, пока пользователь явно не заменил или не удалил его.

### 5.6. Состояния интерфейса

Предусмотреть состояния:

- ожидание ввода;
- генерация;
- успешное завершение;
- ошибка валидации;
- ошибка загрузки модели;
- ошибка синтеза;
- ошибка преобразования в MP3.

## 6. Нефункциональные требования

- Сервис по умолчанию слушает только `127.0.0.1` и недоступен из внешней сети.
- API-ключи и внешние облачные сервисы не используются.
- После первой загрузки модели синтез должен работать без интернета, если все файлы модели сохранены локально.
- Модель загружается один раз при запуске сервера и переиспользуется между запросами.
- Интерфейс не должен зависать во время генерации.
- Одновременно выполняется не более одной тяжёлой задачи синтеза; последующие запросы получают понятный статус или ставятся в очередь.
- Ошибки логируются без сохранения полного пользовательского текста.
- Временные файлы очищаются при штатном завершении и по сроку хранения.
- Код должен запускаться нативно в ARM64-окружении без Rosetta.

## 7. Предлагаемый стек

- Python 3.12 в отдельном виртуальном окружении `.venv`.
- PyTorch 2.x для запуска модели.
- Silero TTS для синтеза речи.
- FastAPI для локального HTTP API.
- Uvicorn для запуска приложения.
- Простой интерфейс на HTML, CSS и JavaScript без тяжёлого frontend-фреймворка.
- FFmpeg для преобразования и объединения аудио.
- Pytest для автоматических тестов.

Все Python-зависимости должны быть зафиксированы в lock-файле или файле с точными версиями после проверки совместимости на M1.

## 8. Архитектура

```text
Браузер
   │
   │ POST /api/speech
   ▼
FastAPI
   │
   ├── проверка текста и параметров
   ├── разбиение длинного текста на фрагменты
   ├── очередь генерации
   ▼
Silero TTS на CPU
   │
   ├── WAV-фрагменты
   ▼
FFmpeg
   │
   ├── объединённый WAV
   └── итоговый MP3
```

### Предлагаемые API-маршруты

- `GET /api/health` — состояние сервера и готовность модели.
- `GET /api/voices` — список доступных голосов и параметров.
- `POST /api/speech` — запуск синтеза.
- `GET /api/jobs/{job_id}` — статус генерации.
- `GET /api/audio/{file_id}` — воспроизведение или скачивание файла.
- `DELETE /api/audio/{file_id}` — удаление результата.

## 9. Этапы реализации

### Этап 1. Изолированное окружение

- Создать `.venv` на Homebrew Python 3.12.
- Установить совместимую ARM64-версию PyTorch.
- Проверить импорт PyTorch и доступность CPU.
- Установить FFmpeg через Homebrew.
- Зафиксировать версии зависимостей.

### Этап 2. Технический прототип Silero

- Загрузить русскую модель Silero.
- Сгенерировать короткую тестовую фразу каждым доступным голосом.
- Проверить WAV 48 кГц.
- Измерить время первой и повторной генерации.
- Проверить использование памяти и нагрев устройства.
- Зафиксировать наиболее стабильный способ загрузки модели.

### Этап 3. Backend

- Реализовать загрузку модели при старте.
- Добавить валидацию входных данных.
- Добавить разбиение длинных текстов.
- Реализовать генерацию WAV.
- Добавить преобразование в MP3.
- Реализовать безопасное хранение и удаление файлов.
- Добавить понятные ответы об ошибках.

### Этап 4. Web-интерфейс

- Создать форму ввода текста.
- Добавить выбор голоса и скорости.
- Добавить индикатор генерации.
- Добавить аудиоплеер.
- Добавить скачивание WAV и MP3.
- Добавить отображение ошибок.

### Этап 5. Тестирование и документация

- Автоматические тесты API и валидации.
- Ручная проверка всех голосов.
- Проверка длинного текста и нескольких последовательных запросов.
- Проверка запуска после перезагрузки компьютера.
- Подготовка `README.md` с установкой, запуском и устранением типовых проблем.

## 10. Критерии приёмки

Задача считается выполненной, если:

- приложение запускается на проверенном MacBook Air M1 одной документированной командой;
- сервер доступен только локально;
- пользователь может вставить русский текст и выбрать один из доступных голосов;
- короткий отрывок успешно превращается в аудио без внешнего API;
- результат воспроизводится в браузере;
- WAV и MP3 скачиваются и открываются стандартными проигрывателями macOS;
- повторная генерация не требует повторной загрузки модели;
- ошибки пустого, слишком длинного или некорректного ввода отображаются понятно;
- текст и аудио не отправляются во внешнюю сеть после локального скачивания модели;
- основные тесты проходят;
- в документации явно указано ограничение некоммерческой лицензии модели.

## 11. Проверки качества

Использовать тестовый набор, содержащий:

- обычный повествовательный текст;
- вопросительные и восклицательные предложения;
- слова с неоднозначным ударением;
- числа, даты и сокращения;
- букву `ё`;
- прямую речь;
- текст длиной более одного внутреннего фрагмента.

Для каждого голоса оценить:

- разборчивость;
- правильность ударений;
- естественность пауз;
- отсутствие обрезанных окончаний;
- отсутствие щелчков при объединении фрагментов;
- время генерации относительно длительности результата.
